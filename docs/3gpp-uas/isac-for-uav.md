## 摘要

Release 20 的 **ISAC（Integrated Sensing and Communication，通信与感知融合/通感一体）for UAV**，是 3GPP 首次将"用蜂窝基站雷达化探测**未联网**低空无人机"从研究推向**规范化**的标准工作。它的战略意义在于：**补齐了 Rel-19 只能管理"合作式"联网无人机的短板，让网络具备对"非合作/黑飞"目标的探测能力**——这正是低空经济安全监管最刚需、也最难的一环。

本报告基于 3GPP 官方文档与产业公开信息逐条核实，核心结论如下：

1. **这不是一个立项，而是四条线并行的体系工程**：RAN1/RAN3 研究项（→ TR 38.765）解决"能不能测、测多准"；SA2 架构研究（FS_Sensing_ARC → TR 23.700-14）与规范项（Sensing-ARC）解决"感知能力怎么进 5GC、怎么开放给应用"；中国电信牵头的 RAN 规范项（**RP-261566**）解决"基站与感知网元之间的架构、流程、信令、数据格式怎么落地"。
2. **技术体制已收敛为"gNB 单站自发自收（mono-static）为主"**：复用现有 CP-OFDM 下行波形与参考信号、不改动终端（No UE impacts）、优先 FR1（4/4.9/6 GHz）。
3. **最关键的工程结论是"多 TRP 融合"**：TR 38.765 的上百个仿真结果显示，单 TRP 在多数配置下达不到 5% 漏检/虚警目标，而多/全 TRP 融合下绝大多数方案达标，最优已达**亚米级定位（0.26 m）与厘米级速度精度（0.02 m/s）**。
4. **架构上做了一个大胆简化**：gNB 通过**新增的 Ns 接口直连核心网感知网元 SenF，绕过 AMF**，配套专用 **NsAP 协议**与 **SCTP** 承载，形成完整的接口管理与感知信息传输流程。
5. **这是首个由中国运营商（中国电信）牵头、46 家公司（含 14 家海内外运营商）支持的低空通感国际标准**，直接回应了"各厂商基站独立测试、无法与核心网/应用打通"的产业痛点。
6. **当前成熟度**：截至 2026-09，Stage 2 刚冻结、Stage 3 规范化（即中国电信 WID）正在进行，预计 **2027-03 Stage 3 冻结、2027-06 ASN.1/OpenAPI 冻结**。**距离可互操作的商用标准约 1 年**。

## 一、为什么是现在：立项背景与三重驱动

### 1.1 低空经济的"非合作探测"刚需

低空经济的安全监管要面对两类目标：

| 目标类型 | 含义 | Rel-19 及之前能否管控 | 典型手段 |
| --- | --- | --- | --- |
| **合作式目标** | 主动联网、上报身份与位置的合规无人机 | ✅ 能（UAS NF / UUAA / Remote ID / 高度上报） | 蜂窝联网 + Remote ID |
| **非合作目标** | 不联网、甚至恶意"黑飞"的无人机 | ❌ 不能——网络感知不到未接入的对象 | 需要"雷达式"探测 |

Rel-15~19 的 3GPP UAS 体系，本质是"**让联网的无人机可管**"；但对不联网的黑飞目标，传统蜂窝网无能为力，只能依赖独立部署的雷达/光电/无线电侦测——**成本高、有盲区、难组网**。

**ISAC 的破局点**：让基站在通信的同时，用同一套射频"顺便"感知周围空间的反射体，从而获得**未接入网络目标**的距离、速度、角度、位置。正如 TR 38.765 开篇所述——现有 5G-A 设计以数据传输为主，虽支持基于 RAT 的定位，但**不具备探测"未连接到网络的对象"的内生能力**；ISAC 正是为此而生。

### 1.2 标准空白制约了产业闭环

在标准缺位的几年里，国内外设备商的通感基站"一直处于独立测试阶段，无法与核心网、应用侧打通，实现感知业务闭环"。中国电信在立项说明中点明的痛点非常具体：**基站能测出数据，但没有统一的架构、信令和数据格式，数据出不了基站、进不了核心网、到不了应用**。ISAC for UAV 规范项要解决的，正是这"最后一公里"的互联互通。

### 1.3 政策与产业的双重推力（中国语境）

- **2026-02-10**，工信部等五部门联合发布《关于加强信息通信业能力建设 支撑低空基础设施发展的实施意见》，提出到 **2027 年全国低空公共航路地面移动通信网络覆盖率不低于 90%**，并将"多元融合感知"（5G-A 通感 + 雷达 + 光电）写入要求。
- **运营商侧**已先行：中国移动建成全球最大规模通感一体试验网，推出全球首款通感一体商用产品；中国电信则直接在 3GPP 牵头国际标准立项。
- 政策的"覆盖率目标"与产业的"标准统一诉求"叠加，使 Rel-20 ISAC for UAV 的立项正当其时。

- **Rel-20（研究与规范并行，本报告主体）**：5G-A 部分把"面向 UAV 的 gNB 单站感知"从研究推进到规范；同期 6G 研究启动，ISAC 被定位为 6G 的**定义性特征**之一。

## 三、技术体制深度解析：怎么测、测多准

> 本章主要依据 **TR 38.765 v20.0.0**（Rel-20 RAN 研究输出），数值均可在原文 Clause 4/5/6/9 核对。

### 3.1 感知模式：单站自发自收为基线

3GPP 收敛的技术路径是 **gNB-based mono-static sensing**——**单一 TRP、感知发射机与接收机共址、自发自收**。选择它的原因：

- **自同步**：收发同站，时延与多普勒可直接读取，无需跨站严格同步；
- **复用现网**：不改动终端（**No UE impacts**），优先 FR1；
- **工程可落地**：与现有基站形态兼容。

代价是要对抗**全双工自干扰**（自身发射泄漏进自身接收机）。研究中通过**天线隔离度（FR1 取 65/80 dB）**与残余自干扰建模（叠加 AWGN）来处理；基站最大发射功率即由"接收机饱和功率 + 天线隔离度"反推（52/37 dBm）。

> 架构上对 **gNB bistatic（一站发、另一站收）** 的适用性"可作为一部分考虑、但无额外架构影响"；**明确不研究 inter-gNB 协调**——这是为了控制 Rel-20 的复杂度，多站协同留待 6G。

### 3.2 波形与资源：复用下行，量化"感知开销"

- **基线波形 CP-OFDM**，**复用现有 DL NR 波形与参考信号**（不为感知新造波形，保证后向兼容）。
- **感知资源比例（Sensing Resource Ratio）**：把资源分为 Type_1（用于感知发射）/ Type_2（其中兼作通信）/ Type_3（因感知无法用于通信），用两种 Option 计算开销占比。评估显示**资源比例 ≤10%** 即可达标——这是"通信不被感知拖累"的关键证据。

理论上，CP-OFDM 单站感知的无模糊范围/速度由波形参数决定：

```
无模糊距离   dmax = c / (2 · Kcomb · Δf)
无模糊速度   vmax = c / (4 · fc · Ts)
速度分辨率   Δv   = c / (2 · fc · M · Ts)
```

（c 光速、Kcomb 梳齿间隔、Δf 子载波间隔、fc 载频、Ts 观测间隔、M 相参观测数。增大梳齿间隔会压缩无模糊距离；延长相参观测则提升速度分辨率。）

### 3.3 评估场景与假设（Annex A / Clause 6.2）

| 参数 | FR1（优先） | FR2-1（可选） |
| --- | --- | --- |
| 场景 | UMa-AV，可选 RMa-AV | UMi-AV |
| 载频 | 4 / 4.9 GHz（可选 6 GHz） | 30 GHz |
| 带宽 / SCS | 100 MHz / 30 kHz | 400 MHz / 120 kHz |
| 站距 | UMa-AV 500 m（可选 1000 m）；RMa-AV 1732 m | UMi-AV 200 m |
| 天线配置 (M,N,P,Mg,Ng;Mp,Np) | Tx/Rx: (8,8,2,1,1;4,8)，d=(0.5,0.8)λ，±45° | (16,16,2,1,1;1,1) |
| 最大发射功率 | **52 dBm / 37 dBm** | 30 dBm |
| 天线隔离度 | 65 / 80 dB | 80~100 dB |

**UAV 目标建模**：小型无人机（0.3×0.4×0.2 m，小尺寸 RCS 模型），中心站每扇区投放 N=5 个目标，**垂直分布 25–300 m**（可选 1.5–300 m），水平速度 0–180 km/h，最小站-目标 3D 距离 10 m，含 LOS/NLOS。这一"**300 m 以下低空**"的设定，与中国低空经济的主流作业高度高度吻合。

### 3.4 性能指标与目标（Clause 4）

TR 38.765 为 UAV 用例 gNB 单站感知定义的目标（Table 4.2-1）：

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 漏检概率 Missed Detection | **5%** | 有目标却没测到 |
| 虚警概率 Type 1 | **5%** | 无目标误报有 |
| 虚警概率 Type 2 | **5%** | 测到对象但关联不上真实目标 |
| 水平定位精度 | **10 m** @ 90% 置信度 | 估计与真值误差 CDF 90 分位 |
| 垂直定位精度 | **10 m** @ 90% 置信度 | 同上 |
| 速度精度 | **5 m/s** @ 90% 置信度 | 含径向/3D 速度 |

> 注意：**感知分辨率、感知服务时延、刷新率在本研究中不作为指标**——它们是服务层（SA1）关注的，RAN 评估聚焦"测得准不准"。

### 3.5 评估结论：多 TRP 融合是达标的"分水岭"

TR 38.765 汇总了数十家公司上百个仿真结果（Clause 6.3 / 9），结论非常清晰：

| 配置 | Baseline 1（52 dBm，80 dB 隔离） | Baseline 2（37 dBm，65 dB 隔离） |
| --- | --- | --- |
| **多/全 TRP 测量融合** | **9/10 家全部达标** | **7/9 家全部达标** |
| **仅单 TRP** | 仅 3/11 家达标 | 仅 2/9 家达标 |

- **核心结论**：**多 TRP 测量融合是达成 UAV 感知目标的关键**；单 TRP 在多数情况下无法满足 5% 漏检与虚警要求（单 TRP 漏检可达 5%–42%，个别方案 Type 1 虚警高达 91%）。
- **最优结果**：在多 TRP + 方向波束 + 高功率配置下，已达**水平定位 0.26 m、3D 速度 0.02 m/s** 的亚米级/厘米级精度——远超 10 m / 5 m/s 的达标线，说明技术上限很高，瓶颈在工程取舍。
- **工程启示**：达标的"甜点"是 **多/全 TRP + 感知资源比例 ≤10% + 方向波束 + 合理 CPI（相干处理间隔）**。

## 四、网络架构与协议深度解析：感知能力怎么进网、怎么开放

### 4.1 测量分级：Level A/B/C/D 的功能分割与带宽权衡

gNB 测到的数据"加工到什么程度再上报"，直接决定传输带宽与网元分工。TR 38.765 定义了四级（Clause 5.1）：

| 级别 | 内容 | gNB 与 SenF 分工 | 传输带宽 | 规范前景 |
| --- | --- | --- | --- | --- |
| **Level A** | 原始信道冲激响应（每子载波/符号/端口的幅度相位） | gNB 几乎不处理 | **极高（每 TRP 数十 Mb~数百 Gb）** | ❌ **否决**（带宽不可接受） |
| **Level B** | Delay/Doppler/Angle 剖面 | gNB 做初步处理出中间剖面，SenF 提取点/径、聚类、跨 gNB 融合、检测跟踪 | 高 | 备选 |
| **Level C** | 检测到的 path/point 参数（range/Doppler/角度/功率/置信度） | gNB 提取点/径，SenF 聚类、跨 gNB 融合、检测跟踪 | **低（每 TRP 数 Kb~数十 Kb）** | ✅ **确定进入规范** |
| **Level D** | 对象/目标级（position/3D 速度/置信度，per gNB） | gNB 完成全部处理与 gNB 内检测跟踪，SenF 做对象级聚合与跨 gNB 跟踪 | **低（每 gNB 约数 Kb）** | ⚠️ 取决于 **SA3 隐私安全**裁定 |

> **结论**：Level C 在"低带宽"与"SenF 保有融合能力"之间取得最佳平衡，**成为唯一确定进入规范阶段的级别**；Level D 因涉及"可被识别为目标级信息"，需待 SA3 解决隐私与安全后方可支持。中国电信牵头的 WID 即明确"**支持 Level C 与 Level D，若安全/隐私问题与 SA3 协同解决**"。

### 4.2 架构：gNB 直连 SenF，绕过 AMF

```
感知服务请求/结果开放 (经 NEF, 服务化总线)
   ┌──────────┐   ①请求    ┌──────────────────────────┐
   │  AF       │ ─────────► │  5GC                      │
   │ (可信/     │            │   ┌──────┐   ┌────────┐  │
   │  第三方)   │ ◄───────── │   │ SenF │◄─►│  NRF   │  │
   └──────────┘   ⑥结果     │   │(感知  │   │(注册/  │  │
                            │   │ 功能) │   │ 发现)  │  │
                            │   └──┬───┘   └────────┘  │
                            └──────┼───────────────────┘
                                   │  Ns 接口 (NsAP / SCTP)
                                   │  【直连, 不经过 AMF】
                              ┌────▼─────┐
                              │   gNB     │  自发自收 mono-static
                              │ (TRP×N)   │  复用 DL 波形感知
                              └────┬─────┘
                                   │ 反射回波
                              ▒▒▒ UAV ▒▒▒  (非合作/黑飞目标)
```

要点：

- **新增 Ns 接口**：gNB 与 SenF（Sensing Function，感知功能网元）之间的**直接接口，不经过 AMF**——这是对 5GC 控制面的一次结构性增强，避免感知大流量数据挤占 AMF。
- **SenF**：SA2 定义的**新控制面逻辑网元**，职责是"收集感知测量数据、计算感知结果、向感知服务消费者开放结果"。它在服务化总线上与其他 NF 交互，**向 NRF 注册其感知能力**，供 AF（可信/第三方）发起请求时**发现与选择**。
- **gNB 自主决定**用于感知的 TRP 与感知资源；SenF 基于 gNB 上报的 **supported sensing area**（经 OAM 和/或 gNB 信令获得）来选择 gNB。
- **协议选型**：评估了"复用 NGAP"与"新建专用协议"两条路，结论是采用**专用应用协议 NsAP**（更干净，但需 CT4 分配新端口号）；数据承载在 SCTP / GTP-U / WebSocket 三选项中选定 **SCTP**（原生分段、可靠按序、拥塞流控，标准化工作量小）。

### 4.3 NsAP 协议流程（Clause 8）

NsAP 提供两大功能，构成完整闭环：

**A. 感知信息传输（Sensing Information Transfer）**

| 流程 | 类别 | 消息 | 作用 |
| --- | --- | --- | --- |
| Sensing Initiation | Class 1 | Sensing Request / Response / Failure | SenF 下发感知请求，携带**感知测量 ID、目标感知区域（3D）、上报模式（一次性/周期/事件触发）**、可选性能要求；gNB 应答并可携带测量结果 |
| Sensing Abort | Class 2 | Sensing Abort | SenF 中止指定测量并释放资源 |
| Sensing Modification | Class 1 | Modification Request / Response / Failure | 修改已有测量的参数 |
| Sensing Failure Indication | Class 2 | Failure Indication | gNB 通知无法继续上报 |
| **Sensing Report** | Class 2 | **Sensing Report** | gNB 按指定模式（一次性/周期/事件）上报 Level B/C/D 测量 |

**B. 接口管理（Interface Management）**

| 流程 | 消息 | 作用 |
| --- | --- | --- |
| **Ns Setup** | Setup Request / Response / Failure | **首个 NsAP 流程**，gNB 上报 **supported sensing area** 等感知能力 |
| RAN Configuration Update | Update / Acknowledge / Failure | gNB 更新感知能力信息 |
| Error Indication | Error Indication | 报告入向消息错误 |

> 这套"先 Ns Setup 建立能力 → 再 Initiation 发起任务 → 周期/事件 Report 上报 → 可 Modification/Abort"的模型，与定位（LCS/LMF）的流程范式一致，但面向"探测未联网目标"做了专门设计。

### 4.4 SA2 侧：感知服务如何端到端运转

SA2 的 Sensing-ARC 规范（基于 TR 23.700-14 结论）围绕 **6 个关键问题（KI）** 展开，勾勒出端到端服务链：

| KI | 主题 | 解决什么 |
| --- | --- | --- |
| KI#1 | 系统架构支持感知服务 | SenF 等新网元如何嵌入 5GC 服务化架构 |
| KI#2 | 授权与撤销 | 谁能发起感知服务、如何回收权限 |
| KI#3 | 感知实体/功能发现与重选 | 按服务需求与能力，选哪个 SenF / 哪些 gNB |
| KI#4 | 感知数据收集与传输 | 测量数据如何汇集以计算结果 |
| KI#5 | 感知结果开放 | 一次性/周期/事件地把结果（含上下文）开放给消费者 |
| KI#6 | 感知实体参数配置 | 感知相关参数如何配置下发 |

**隐私/安全/计费被显式"外挂"协调**：隐私与 SA3 协同、计费与 SA5 协同、RAN 相关与 RAN WGs 协同——这说明 3GPP 把感知数据（可能涉及对人和物的监控）当作**高度敏感资产**来对待。

## 五、感知 KPI 的"三层数值"对照（最易混淆处，务必厘清）

低空无人机感知的精度指标，在不同文档里数值差异很大，因为它们处于**不同层次、不同成熟度**。下表厘清：

| 层次 | 文档 | 水平定位 | 速度 | 漏检/虚警 | 时延 | 性质 |
| --- | --- | --- | --- | --- | --- | --- |
| **SA1 服务需求（理想目标）** | TR 22.837 Table 5.10.6-1（UAV 航迹追踪） | **1–2 m** | 1–2 m/s | —（分辨率距离 1–10 m） | 100–1000 ms | 服务层想要达到的水平 |
| **Rel-20 5G-A 评估基线** | TR 38.765 Table 4.2-1 | **10 m** @90% | 5 m/s @90% | 5% / 5% | 不评估 | 本 Release 验证可行性的门槛 |
| **Rel-20 评估最优实测（仿真）** | TR 38.765 Clause 6.3 | **0.26 m** | 0.02 m/s | 可远低于 5% | — | 技术上限（多 TRP 融合） |
| **6G 提案目标（未来）** | RAN#110 vivo 提案 Table 2 | **2 m** | 2 m/s | 5% / 5% | <1000 ms | 6G 研究的进取目标 |
| **国内产业现网（工程现状）** | 中国移动商用产品 | **20 m**（300 m 以下 RCS 0.01㎡） | — | 漏检<5% | — | 已商用；厦门试验达**分米级** |

**三点洞察**：

1. **评估基线（10 m）比服务需求（1–2 m）宽松**，是"先证明可行、再逐步逼近"的标准化惯例；仿真最优已达 0.26 m，说明 1–2 m 的服务需求并非遥不可及。
2. **现网商用（20 m）落后于仿真上限（0.26 m）**，差距来自真实杂波、多目标、成本与功耗约束——这正是标准统一后、规模商用要弥合的。
3. **不要拿 6G 的 2 m 目标去要求 Rel-20**；Rel-20 的历史任务是把"架构—信令—数据格式"跑通，性能压榨留给 6G。

## 六、产业落地与国内外进展

### 6.1 标准主导权：中国运营商首次牵头低空通感国际标准

- **中国电信**牵头 **RP-261566**（New WID on ISAC for NR），中国电信研究院担任报告人（Zheng JIANG），**46 家公司（含 14 家海内外运营商）支持**。

### 6.2 国内运营商与设备商实践

| 主体 | 进展 | 关键指标 |
| --- | --- | --- |
| **中国移动** | 全球最大规模通感一体试验网；合肥公安低空安防样板；全球首款通感一体商用产品 | 300 m 连续探测；600 m 以下全量监测，探测概率 99%、识别准确率 98%、航迹稳定 95%；商用产品位置精度 20 m、漏检<5% |
| **中国电信** | 牵头 3GPP ISAC WID；研究院主导标准化 | 聚焦基站自发自收模式，打通"基站—核心网—应用"闭环 |
| **中兴通讯** | 5G MIMO 相控阵通感；多模态融合（Remote ID + 5G-A + 无线电侦测 + 雷达 + 光电）落地十五运会等 | 通信/辅助导航/感知三功能一体 |

### 6.3 三种感知模式与组网思路

国内产业已形成清晰的分级建设思路：

- **单站感知**（自发自收全双工，对应 3GPP mono-static 基线）：需收发隔离与射频自干扰消除；
- **双站感知**（A 发 B 收，对应 bistatic）：无需全双工，但需严格时频同步；
- **端网协作感知**（基站发终端收等）：借助靠近目标的终端提升覆盖。

组网分层：**300 m 以下**复用地面移动网 + 新建 5G-A 基站连续覆盖；**城市 600 m 以下**增强 5G-A 能力；**600 m 以上**协同专频与卫星。配合"哈勃一号"机载终端与"四码合一"认证，形成"身份可信—飞行可控—全域可探"的闭环。

### 6.4 国际对照

- **公共安全驱动**：美国 FirstNet Authority 在 RAN 全会上明确支持 ISAC for UAV，看重其"在覆盖区内获取目标的距离、速度、位置、尺寸、材质"的态势感知能力。
- **ITU/ETSI 协同**：ITU-R M.2160 与 ETSI ISG ISAC 提供 IMT-2030 用例/KPI/信道/架构/评估的互补语境；3GPP Rel-20 的工作与 6G 愿景（TR 22.870）无缝衔接。

## 七、成熟度研判与风险提示

| 维度 | 现状 | 研判 |
| --- | --- | --- |
| **标准化阶段** | Stage 2 刚冻结（2026-09，TSG#113）；Stage 3（中国电信 WID）进行中 | ⏳ **距可互操作商用约 1 年**（2027-03 Stage 3 冻结、2027-06 ASN.1/OpenAPI 冻结） |
| **技术可行性** | TR 38.765 证明多 TRP 融合可稳定达标，上限亚米级 | ✅ 原理已验证，工程化是关键 |
| **隐私安全** | Level D 目标级上报待 SA3 裁定；感知数据涉监控敏感 | ⚠️ **最大不确定性**，可能收紧数据开放粒度 |
| **单站 vs 多站** | Rel-20 只做单站（无 inter-gNB 协调） | ⚠️ 广域无缝覆盖需多站协同，留待 6G |
| **现网差距** | 商用 20 m vs 仿真上限 0.26 m | ⚠️ 杂波抑制、多目标、成本功耗待弥合 |
| **频谱与监管** | 优先 FR1（4/4.9/6 GHz）；低空频率规划国内尚在明确 | ⚠️ 频率政策会影响部署节奏 |

**总体判断**：Rel-20 ISAC for UAV 已完成"从 0 到 1"的标准破局——**架构、信令、数据格式三件套齐了，技术可行性经多 TRP 仿真验证**。它是 5G-A 低空通感规模商用的"标准地基"，也是 6G 通感融合的先导。未来一年的看点是 Stage 3 细节落地与 SA3 隐私安全结论。

## 八、对中国低空经济的启示

1. **能直接用的**：单站自发自收感知模式、Level C 数据格式、Ns 接口 + NsAP 流程，与国内"4.9 GHz 通感一体""300 m 低空探测"的技术路线**高度一致**，可作为设备研发与组网设计的直接依据。
2. **需要本地化衔接的**：感知结果的**开放对象与权限**（公安/空管/运营平台）、与 **UOM 平台**及"一机一码"实名体系的数据打通、**多元融合**（5G-A 通感 + 雷达 + 光电）的统一评价体系——这些超出 3GPP 范畴，需国内标准（CCSA）与监管规则补齐。
3. **卡点在**：① 低空频率规划与专用号段落地；② Level D 目标级数据的隐私安全边界（关系到能否做"识别到具体目标"的高级应用）；③ 多站协同与广域覆盖（Rel-20 未覆盖，需等 6G 或先做厂商私有方案）。
4. **战略建议**：利用"中国电信牵头标准 + 移动/中兴规模试验"的窗口期，**把现网试验数据反哺 Stage 3 标准化**（尤其杂波建模、多目标、Level D 隐私方案），推动中国方案写入国际标准，同时以 CCSA 承接 3GPP 未覆盖的融合感知与平台对接。

### B. 核心术语

- **ISAC**：Integrated Sensing and Communication，通信与感知融合（通感一体）
- **Mono-static / Bistatic**：单站（收发共址）/ 双站（收发分址）感知
- **SenF**：Sensing Function，感知功能网元（5GC 新增控制面逻辑网元）
- **Ns / NsAP**：gNB 与 SenF 间接口 / 其专用应用协议（承载于 SCTP）
- **TRP**：Transmission Reception Point，发送接收点
- **Level A/B/C/D**：感知测量的四级加工程度（原始→剖面→点/径→对象级）
- **RCS**：Radar Cross-Section，雷达散射截面积
- **CPI**：Coherent Processing Interval，相干处理间隔
- **MD / FA**：Missed Detection 漏检 / False Alarm 虚警
